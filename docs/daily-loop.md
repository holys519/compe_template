# 日次ループ（対戦系コンペ）

> **適用条件: ライブ ladder のあるコンペ。表形式・CV・NLP では ladder 監視の代わりに検証・データ誤りのレビューを置く。レビューは重要な判断の前に限定し、工数上限を決める。実装ブロック（WIP 制限）を先に確保する。**

## 朝
1. ライブ集計（アクティブ提出 ID を API で確認して差し替え）: W-T-L と tie 込みスコア、相手帯別、相手の開幕/系統別。tie を負けに数えない。
2. 主要 README・進捗ノート（`docs/research/progress_<date>.md`）を更新して push。
3. 外部レビュー 3 観点（実装監査・評価手法・研究案）→ データで反論・補足して 1 往復。
4. 合意した項目を `expNNN` として事前登録（spec.toml、seed 台帳）し、ゲートを起動。
5. `docs/research/<review>/discussion_log.md` に要点と採否を追記して push。
6. ユーザーへ要約（ライブ、指摘、開始した実験、**承認が必要な提出**）。

## 夕
1. 朝に起動したゲートの集計 → README/spec 更新 → 合格なら候補として報告（提出は承認制）。
2. ライブ更新。3. レビューに結果と次の仮説を渡して 1 往復（実装のずれ・考察のボトルネックの検閲）。4. discussion_log 追記・push。5. 要約報告。
- 1 日の終わりに「宣言したが未着手」を 1 行書く。
