# Evaluation protocol（対戦・シミュレーション系コンペ用。kaggriculture 2026-09 の教訓から）

> **適用条件: 対戦・シミュレーション系（同 seed で再現できる環境）。表形式・画像・NLP では「独立単位」を seed ではなく患者/サイト/文書グループに置き換え、one look は最終確認にだけ適用する。数値（sd 11-26k、640 seed）は kaggriculture の作業例であり、分散・最小効果・検出力から計算し直す。**

## 1. 物差しを先に決める
- 順位を決める量（例: rating / Bradley-Terry の勝敗）を分解した**得点表**を最初の 2 日で作る: 相手帯 × 決着（大勝・僅差勝ち・tie・小差負け・大差負け）。伸びしろの大きい所に時間を配分する。
- ローカル指標（平均資金・平均スコア）が本番順位と相関するかを 1 週目に確認する。kaggriculture ではローカル平均資金と live rating の順位相関が **−0.79** だった。
- 物差しは 3 層: (a) 上位との**構造プロファイル距離**（seed 非依存。例: d10 の区画数・植付数、施肥回数、稼働率）、(b) 事前登録の**対比較**、(c) **上位の録画をそのまま相手にした**評価（市場など共有資源の影響込み）。単一の相手との資金差だけで判断しない。

## 2. seed 台帳と事前登録
- `docs/evaluation-protocol.md`（本ファイル）末尾に台帳表を置き、**使う前に** `| seed 範囲 | 実験 | 用途 | 日付 |` を登録。確認用 seed は screen・開発・診断と重ねない。自動ループの追記は**セッションごとに別ファイル**（rebase 競合を避ける）。
- spec.toml に B（凍結ベース）/ C（候補）/ R（参照相手）/ seeds / decision / guards を実行前に書く。結果を見てから条件を変えない（変えるなら新しい実験）。

## 3. 対比較の規則（one look）
- 同 seed・**両席**（席の相関 ≈0.9 なので 2 観測ではなく席平均を 1 観測）。seed 内の差 D_s の平均と t 区間。
- サンプル: seed 内 sd 11-26k なら 640 seed で ±2k、+3k を 80% で検出。**20 seed screen は +7-17k しか検出できず、真の 0 を 37% 通し、真の +2k を 37% 落とす**（偽陽性 3/4 を実測）。screen はフィルタであり証拠ではない。
- 決定: L>0 採用 / U<0 却下 / U<min_effect 停止 / それ以外 保留。**1 回だけ見る**。seed を追加して救済しない。繰り返し確認する開発では α=0.005（800 seed）か α 消費計画。
- 累積効果は増分の合計ではなく、**凍結した端点同士を新規 seed で 1 回**測る（選択バイアスと参照の変更を除く）。

## 4. 無言の失敗を疑う
- エージェントの例外→PASS フォールバックは「エラー 0・初期資金のまま」を生む。telemetry（例外数・フォールバック数）と**生産指標の構造ガード**（植付数・家畜数・最終資金の下限）を必須にする。
- 新しいエンジン・ランナー（Rust 移植、GPU 環境）は最初に **同一性確認**（同 seed 20 × 両席で最終状態が一致）。不一致は agent 側の決定性バグ（前試合の状態の持ち越し）の発見にもなる。
- 測定コードは 2 通りで数えて一致を確認（スナップショット差分 vs 行動レベル台帳）。要求数と約定数、PASS の分母、ユニット番号の意味（人物か雇用枠か）を明記する。

## 5. 同一 seed ≠ 同一世界
- 乱数を共有する副作用（kaggriculture: 雑草の抽選が店の抽選を動かす）があると、方針が変わると世界も変わる。ペアリングの分散削減は弱くなる。可能なら店/世界を固定した診断と、素のエンジンでの確認を分ける。
